## J. D-1 daily state の設計（schema未実装）

将来の14系列は `FIRST_COURSE_1..6`、`EXACT_SECOND_COURSE_1..6`、`OVERALL`、`SHORT_50`。1～12系列のコースは `core.race_result.actual_course` に限る。2着は `finish_position=2` のみ。

1. `rating_run` 相当の論理 record に `dataset_version` と source manifest/hash、eligibility rule version、finish-state classification version、method version、parameter version、学習・選定 cutoff、採用有効期間を紐付ける。今回の監査の DB snapshot ID を将来の dataset version に流用しない。
2. `rating_daily_state` 相当の一意キーを `(rating_run, business_date, player_id, rating_series)` とし、`rating_value`、`effective_from=business_date`、`source_cutoff_date=business_date-1`、method/parameter/dataset version、生成時刻、入力 hash を保持する。欠測・未初期化は数値0で表さない。
3. D状態はD-1までに確定かつ利用可能な結果を閉じてから一括生成し、Dの全 race が同じ immutable state ID を参照する。Dの結果はDの全 race 終了後に処理し、D+1以降にだけ反映する。D当日の1R→2R更新は禁止。
4. `player_debut_event` 相当には first observed race、cohort raw/正規化、cohort 月、coverage 開始と証拠、判定状態、判定時刻、effective date を持たせる。D日同時新人は `(D, series)` で一組にし、投入前の既存有効選手母集団を固定して平均を**一度**計算し、全員に同じ `平均×0.8` を付ける。14系列ごとの母集団数・平均・倍率・除外された同日新人集合と version を保存する。今回は平均・Rating値を計算していない。

Dの全 roster が state 凍結前に分かるとは未確認。後から初出走が見つかった場合の扱いは、同日 state を書き換えず、明示的な未利用状態または次日有効などの規則を別途決める。過去結果の公表時刻も現保存資料だけでは復元できず、`race_date < D` は必要条件であって十分条件ではない。

## K. 2026 versioning readiness

2026-01-01、01-08、01-15…の7日ごとの再評価には、各選定時点以前のデータだけを使い、`method_version`、`parameter_version`、`selected_at`、`training_cutoff`、`effective_from/to`、source/dataset version を固定する。2026-01-01更新の最大結果 cutoff は2025-12-31、01-08更新は2026-01-07。7日は再評価 cadence であり、訓練窓長ではない。選定時刻までの結果利用可能性を別途証明する。2025 holdoutを見て2023～2024手法を再調整し、同じ2025を独立holdoutと再表示しない。
